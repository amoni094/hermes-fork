# Hermes Memory Wiki reconnaissance

Use this playbook when an Obsidian vault contains an Hermes Memory Wiki or similar generated knowledge layer.

## Fast orientation order

1. Open the vault home note / dashboard first.
2. Read the wiki index page to learn the page classes and counts.
3. Read the operating-model / canonical workflow note to understand how the vault wants to be used.
4. Read the syntheses index before drilling into individual sources.
5. Read the reports index to find gaps, open questions, and weak provenance.
6. Read the main memory bridge source to see the actual durable workspace index behind the wiki.

## What to look for

- Counts and coverage: total pages, source pages, syntheses, reports.
- Open questions and low-confidence pages: good starting points for follow-up.
- Generated blocks inside managed markers: treat as plugin-owned; preserve them unless you are updating the generator.
- Human notes outside managed markers: preserve and prefer them for durable additions.
- The source bridge page: it often reveals whether the wiki is a mirror of a live workspace memory index or a broader human-curated layer.

## Reading posture

- Prefer source-backed claims over repeating wiki-to-wiki summaries.
- Treat indexes and reports as navigation aids, not as the final truth.
- If the wiki shows early-stage reports like empty provenance or relationship graphs, use that as a signal that the knowledge graph is still maturing.
- Keep the output concise: report the most useful durable takeaways, not every page name.
