# Thunderbird email workflow preference

Session lesson:
- The user clarified a durable workflow preference for direct email requests.
- When they say 'email this to <recipient>', the expected path is to use Thunderbird, sign the message as Alexey, and send automatically unless they explicitly ask for a draft.

Operational takeaway:
- Treat this as a task-workflow preference, not merely a contact-permission fact.
- For exact-recipient email requests, do not default to a pasteable draft when a Thunderbird path is available.
- Compose with the user's preferred sign-off name.
- Separate workflow preference from capability verification: only claim 'sent' after a real outbound send path succeeds; if automation only opens a compose window, state that limitation plainly.
