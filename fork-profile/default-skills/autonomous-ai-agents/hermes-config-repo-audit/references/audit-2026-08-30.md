## New pitfalls discovered this session

### validate_repo.py exact-phrase check on current-workflow.md
The validator has TWO exact-phrase checks:
1. README.md must contain `sanitized copy of the active Hermes config` (documented)
2. current-workflow.md must contain ALL THREE of these exact substrings:
   - `~/.hermes/.env`
   - `~/.hermes/auth.json`
   - `raw gateway/session/chat histories` (lowercase 'r' — case-sensitive)
Capitalizing 'Raw' silently fails the check (exit code 1, one-line error message).
Fix: write the exclusions list verbatim or check via `grep -c 'raw gateway' docs/current-workflow.md`
before running validate_repo.py.

### cron.snapshot.json programmatic verification pattern
After writing cron.snapshot.json, verify with an inline script:
```python
import json, pathlib
data = json.loads(pathlib.Path('hermes-config/cron.snapshot.json').read_text())
assert data['total_jobs'] == len(data['jobs'])          # count integrity
assert {j['name'] for j in data['jobs']} == EXPECTED_NAMES  # name set match
# spot-check key new jobs:
new_job = next(j for j in data['jobs'] if j['name'] == 'hermes-research-weekly')
assert new_job['schedule'] == '0 6 * * 2'
assert new_job['script'] == 'hermes-research-sweep.py'
```
Do this before committing — a hand-written snapshot can have off-by-one total_jobs
or a mistyped schedule without the JSON linter catching it.

### generate_skill_inventory.py writes files, not just stdout
`python3 scripts/generate_skill_inventory.py` writes BOTH:
- `docs/skill-inventory-authoritative.json`
- `docs/skill-inventory-authoritative.md`
The JSON summary on stdout is just a print at line 224; the actual atomic writes happen
at lines 187 and 223. Do not assume it's dry-run because it printed to stdout.
Just run it — the files will be updated in place.
