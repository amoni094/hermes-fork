PRIMER: Algebraic Topology / Topological Data Analysis (TDA)

FIELD OVERVIEW

Algebraic topology studies shapes and spaces through invariants that survive continuous deformation. TDA applies these tools to finite point clouds and noisy datasets by building simplicial complexes (unions of vertices, edges, triangles, tetrahedra) and computing their topological features. The core objects are simplicial complexes, homology groups (which count connected components, holes, voids), persistent homology (how features appear/disappear as parameters vary), Betti numbers (rank of homology groups), and Mapper (a graph-based visualization of data structure). Why it matters: topological features like connected components, loops, and cavities are often more robust to noise and irrelevant detail than geometric features. A point cloud may have arbitrary distances, but its "shape" persists. This formalism quantifies that intuition. For AI systems, TDA offers a way to characterize the structure of learned representations, agent trajectory spaces, and knowledge bases without assuming metric structure or requiring labeled ground truth.

KEY RESULTS

Stability Theorem (Cohen-Steiger, 2010): If two point clouds X and Y have Hausdorff distance d, their persistence diagrams differ by at most d in the bottleneck distance. Formally, if PD(X) and PD(Y) are persistence diagrams (multisets of (birth, death) pairs), then d_B(PD(X), PD(Y)) ≤ d_H(X, Y). This guarantees small perturbations yield small topological changes—critical for robustness. Persistent homology computation: given a filtration (nested sequence of complexes K_0 ⊆ K_1 ⊆ ... ⊆ K_m), compute homology at each step and track when cycles are born and killed. Complexity is O(n^3) for n points in worst case (typically O(n log n) to O(n^2) in practice). Vietoris-Rips filtration: for radius parameter ε, include a simplex if all pairwise distances ≤ ε. Mapper algorithm: discretize data by cover (e.g., overlapping intervals of a filter function), build a graph of connected components in each bin, return a simplicial graph. Key insight: Mapper trades off fidelity for interpretability. Betti number b_k counts k-dimensional holes: b_0 = connected components, b_1 = loops, b_2 = voids. These are computable invariants of homology groups H_k(X).

STANDARD PRACTITIONER TOOLS

Ripser (C++, Python): computes persistent homology from point clouds in milliseconds for moderate sizes (< 10k points). Giotto-tda: scikit-learn-compatible pipeline for TDA (persistence, Mapper, feature extraction). GUDHI: open-source C++ library with Python bindings; supports Rips, Delaunay, alpha complexes. Perseus: optimized for 3D data. Practitioners regularly compute persistence diagrams (plot births vs. deaths, identify significant features by distance from diagonal), barcode plots (horizontal segments showing feature lifetime), and Betti curves (count of alive features at each filtration step). Common preprocessing: normalize point cloud, remove outliers, standardize coordinates. Key formula: for Rips complex at scale ε, simplex {v_0, ..., v_k} included if max pairwise distance d(v_i, v_j) ≤ ε. Homology computation via matrix reduction: update boundary matrix column-by-column to find pivot rows, recording birth/death pairs.

HERMES APPLICATIONS

Application 1: Skill Embedding Redundancy Detection

(a) Mathematical structure: Skills loaded per task type can be embedded as vectors (e.g., via encoder or learned representation). These vectors form a point cloud in d-dimensional space. TDA applied to this cloud yields a persistence diagram and a connected component graph. The Betti curve b_0(ε) tracks how many connected "skill clusters" exist at different scales ε. Persistent homology reveals which clusters are stable (long bars in barcode) versus noise.

(b) Current Hermes approach: skillopt quality scorer ranks individual skills. Redundancy detection is heuristic: similar skill names or overlap in task keywords trigger warnings. No principled detection of skill cluster structure.

(c) Principled TDA approach: Embed all skills as vectors (768-d from a pretrained encoder). Build Vietoris-Rips complex. Compute persistent homology. For each skill, assign to its connected component at filtration step ε* where b_0(ε*) stabilizes (e.g., where Betti curve plateaus). Skills in the same stable component are topologically redundant. Formula: if skill s_i and s_j are in the same connected component for all ε in interval [ε_low, ε_high] where length(ε_high - ε_low) > threshold, merge or flag for review. Use Mapper to visualize skill landscape: partition by PCA projection, compute connected components in each bin, build graph. Nodes are skill clusters, edges indicate proximity. Provide skillopt an explicit redundancy score: (# skills in component - 1) / (component diameter in embedding space).

(d) Value assessment: Medium-to-high value, moderate implementation cost. Skill redundancy is a real problem in Hermes (cron agents accumulate similar procedural knowledge). However, the gain depends on skill vector quality. If embeddings don't capture semantic similarity well, TDA will echo that garbage. Practical risk: embeddings may cluster by task metadata (e.g., "database" skills all near each other) rather than functionality. Mitigation: retrain embeddings on skill execution traces (what arguments, outputs does each skill produce?) rather than text alone. Implementation takes 1-2 weeks (integrate Ripser, build embedding pipeline). ROI: if Hermes runs 25 crons and 20% are redundant, automated clustering saves significant token budget per sweep. Worthwhile if skill inventory reaches > 50 unique skills.

Application 2: Session Trajectory Topology

(a) Mathematical structure: A session is a sequence of (model_choice, tool_call, outcome, token_delta) tuples. Normalize into a point cloud where each turn is a point in a feature space: (latent_model_id, tool_embedding, outcome_code, token_ratio). This space has natural geometry. TDA reveals whether sessions occupy a few distinct "strategy regions" (connected components/clusters) or wander a continuum. Persistent homology detects loops: does the agent cycle through the same tool calls? Does b_1 > 0 indicate a loop structure (persistent hole)?

(b) Current Hermes approach: hindsight summarization records successes and failures as text. No explicit structural analysis of trajectory. Token budget is checked per turn, but no topological view of budget usage patterns.

(c) Principled TDA approach: Featurize each turn as (model_id_one_hot, tool_embedding, outcome_one_hot, token_spent_normalized). Stack into a point cloud of n points (one per turn in session). Compute Rips complex and persistent homology. Inspect Betti numbers: b_0 (# disconnected trajectory regions—do certain task types have isolated solution paths?), b_1 (# loops—does agent retry same tool?), b_2 (voids—complex cyclic dependencies). Use Mapper: filter by token spent; in each bin, compute connected components of trajectory neighborhoods. Resulting graph shows "token budget regimes" and which tools dominate in each. Algorithm: for each session, compute persistence diagram. Extract feature vector: [b_0_max, b_1_max, total_persistence, dominant_feature_scale]. Cluster sessions by these features. Sessions with similar topology are strategically similar; anomalies (unexpected Betti numbers) flag errors or novel behaviors. Formula: b_1 > 0 for persistent session → potential infinite loop or retry pattern.

(d) Value assessment: Medium value, lower priority than skill redundancy. Sessions are inherently sequential and already well-logged. TDA adds interpretability ("this session has a 3-loop structure") but may not improve agent behavior directly. Real gain: detecting anomalous trajectory topology could flag failing agents earlier (e.g., b_1 spike = unexpected retries = resource exhaustion). Implementation cost: moderate (featurization is straightforward, Ripser is fast for n<1000 points per session). Risk: topological features may be unstable if featurization is crude (one-hot vectors are sparse; tool embeddings may not capture semantics). Recommendation: low-priority spike. Implement only if token budget overspend becomes a frequent issue.
