PRIMER: Convex Analysis and Optimization

FIELD OVERVIEW

Convex analysis studies the geometry and calculus of convex sets and functions—shapes and objective functions where line segments between any two points stay inside the set, and weighted averages of function values stay below the function evaluated at weighted averages of inputs. Optimization in this setting is about minimizing or maximizing such functions subject to convex constraints. The field's power lies in guarantees: convex problems have no spurious local minima, algorithms converge to globally optimal solutions with measurable rates, and duality reveals hidden problem structure. For Hermes, convexity matters because agent resource allocation, scheduling, and multi-objective tradeoffs often embed convex structure—even when wrapped in discrete or stochastic layers. Core objects: convex sets, convex functions, subgradients (generalized derivatives), Lagrangian duality, proximal operators, and descent algorithms (gradient, mirror, Frank-Wolfe). Why it matters: many hard-seeming agent problems decompose into convex cores that admit efficient, certified solutions.

KEY RESULTS

Strong Duality and Slater Condition: For a convex problem minimize f(x) subject to g_i(x) <= 0 (convex g_i) and h_j(x) = 0 (affine h_j), if there exists a point where all inequality constraints are strictly satisfied (Slater condition), then the primal optimum equals the dual optimum: min_x [f(x) + sum_i lambda_i g_i(x) + sum_j mu_j h_j(x)] over lambda_i >= 0, with no duality gap. This justifies decomposition and distributed solving.

Proximal Gradient Convergence: For f = g + h where g is smooth (Lipschitz gradient) and h is convex (possibly nonsmooth), the proximal gradient method x_{k+1} = prox_{step*h}(x_k - step*grad g(x_k)) converges in O(1/k) iterations to optimum if step <= 1/L_g (L_g is Lipschitz constant). With acceleration, O(1/k^2).

Mirror Descent Regret: In online convex optimization with losses f_1, f_2, ..., f_T, mirror descent with step size O(1/sqrt(T)) guarantees regret sum_t [f_t(x_t) - f_t(x*)] = O(sqrt(T)) for any sequence of convex losses and any comparison point x*. The algorithm adapts to geometry via a Bregman divergence.

Frank-Wolfe Linear Convergence: On strongly convex objectives over compact convex sets, Frank-Wolfe (conditional gradient) achieves f(x_k) - f(x*) <= O(1/k) without computing projections—only linear oracle calls. Useful when the feasible set is implicit (e.g., a simplex or l1 ball) and projection is expensive.

STANDARD PRACTITIONER TOOLS

CVX (MATLAB/Python), CVXPY (Python), Convex.jl (Julia) for modeling and solving convex programs via disciplined convex programming (DCP). MOSEK, Gurobi for conic solvers. Proximal operator libraries (ProximalOperators.jl, PyProxOp). Automatic differentiation (JAX, PyTorch) for computing subgradients and Jacobians. Standard algorithms: ADMM (alternating direction method of multipliers) for distributed consensus, stochastic gradient descent (SGD) for large-scale, coordinate descent for block structure. Manual tricks: Lagrange multiplier heuristics, warm-starting, and sensitivity analysis for what-if reasoning about constraint tightness.

HERMES APPLICATIONS

1. SKILL SCORING OPTIMIZATION (skillopt module)

Mathematical structure: Skill quality is inherently multi-dimensional (accuracy on task holdout, latency percentile, token efficiency, user satisfaction). Aggregating these into a scalar score subject to a budget constraint (evaluation time, human review capacity) is a constrained optimization problem. The score function is often separable: total score = sum over dimensions of w_d * f_d(performance_d), where w_d are weights and f_d maps performance metrics to utility (often submodular or concave—diminishing returns). The constraint is affine: sum over skills of evaluation_cost_s * indicator(evaluate_s) <= budget.

Current approach: Hermes likely uses hand-tuned weights, greedy skill selection (score per unit cost), and occasional A/B testing. This ignores correlation between skill dimensions and does not adapt weights as new skills arrive.

Principled approach: Formulate as a convex constrained optimization: minimize -sum_d w_d * f_d(perf_d) subject to evaluation_cost_d <= budget and perf_d in [0,1]. If f_d are concave (realistic for utility functions), this is convex. Use proximal gradient or Frank-Wolfe to solve offline before each evaluation cycle. For online adaptation, use mirror descent with step size sqrt(t) where t is the number of rounds; regret is O(sqrt(T)) over T skills evaluated, converging to near-optimal weight allocation. Compute subgradients via finite differences on held-out test sets.

Value assessment: Medium-high. Skill scoring is non-critical (Hermes degrades gracefully with suboptimal skill selection), but a 10-20% improvement in skill utility per evaluation budget is tangible and easy to measure (log skill usage and quality over time). Implementation requires ~200 lines to formulate, solve, and log; the risk is low because the convex relaxation is sound and you can fall back to greedy if solves fail. Main obstacle: defining concave f_d is an art, not a formula.

2. TOKEN BUDGET ALLOCATION ACROSS MULTI-STEP TASKS

Mathematical structure: A task has T sequential steps. Step t routes to model m_t with cost c_{t,m} tokens and expected quality q_{t,m}. Total token budget is B. Hermes must assign (step, model) pairs to maximize cumulative quality sum_t q_{t,m_t} subject to sum_t c_{t,m_t} <= B. This is a bounded knapsack problem with sequential structure (order matters for context carryover). The quality q_{t,m} is often learned from past runs (convex or concave empirically—need to check). If convex or linear in quality (or if you use concave upper bounds), the problem is convex.

Current approach: Hermes likely uses a heuristic: allocate tokens proportionally to step criticality (determined by human domain knowledge or past success rates) and route each step to the cheapest model that meets a quality threshold. This is brittle when thresholds are misset and does not adapt to changing task complexity.

Principled approach: Formulate as maximize sum_t log(1 + q_{t,m_t}) subject to sum_t c_{t,m_t} <= B and m_t in {Claude, GPT, Grok, Mistral}. The log transform enforces diminishing utility (log-concave objective, thus convex problem when minimizing). Solve via Lagrangian dual: for each Lagrange multiplier lambda > 0 (representing token cost shadow price), compute argmax over (step, model) pairs of q_{t,m} - lambda * c_{t,m}, then binary search on lambda to satisfy the token constraint. This takes O(T * num_models * log(B)) time and gives the optimal per-step model routing and proves how much additional utility you gain per extra token—useful for contract negotiation with model providers.

Value assessment: High if tasks are long (T > 5 steps) and token costs vary widely (e.g., Mistral-Small is 0.1x GPT cost). Saves 5-15% of tokens for same quality or improves quality 10-20% for fixed token budget. Implementation: ~150 lines (Lagrangian solver + binary search). Risk: moderate. If quality q_{t,m} is truly non-convex (rare but possible for adversarial task sequences), the algorithm may miss the global optimum, but in practice, convex relaxations are tight. Validate on held-out tasks before rolling out.
