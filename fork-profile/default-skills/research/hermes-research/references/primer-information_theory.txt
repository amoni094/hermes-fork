PRIMER: Information Theory

Entropy H(X) is the expected bits needed to name a sample from P(X): H(X) = -Σ p(x) log p(x). Rare events cost more bits; a deterministic variable has H=0. Conditional entropy H(X|Y) is leftover uncertainty in X after seeing Y. Mutual information I(X;Y)=H(X)-H(X|Y)=H(Y)-H(Y|X) is shared bits: how much observing one shrinks the other. KL D_KL(P||Q)=Σ p log(p/q) is extra bits to code P with a code built for Q; asymmetric, infinite if Q misses P's support. JS is the symmetrized, bounded sibling. Channel capacity C=max I(X;Y) over input distributions is the highest reliable rate through a noisy map X→Y. Rate-distortion: given a distortion d(x,x̂), R(D) is the fewest bits that keep E[d]≤D. MDL: pick the hypothesis whose total description length (model + residual) is shortest. Information bottleneck: find Z that minimizes I(X;Z)-β I(Z;Y) — compress X while keeping what predicts Y.

Key results. Source coding: you cannot losslessly encode iid X below H(X) bits/symbol; you can get arbitrarily close. Channel coding: rates below C are achievable with vanishing error; above C they are not. Data processing inequality: I(X;Z)≤I(X;Y) for any Markov chain X→Y→Z; processing never creates information about X. Fano: if you guess X from Y with error Pe, H(X|Y)≤h(Pe)+Pe log(|X|-1); high remaining entropy forces high error. Rate-distortion tradeoff: R(D) is decreasing and convex; below it, that distortion is impossible.

Tools. Entropy of text is estimated by plug-in (biased high on sparse support), NSB/Chao, or model cross-entropy (nats of -log p_model). KL/JS on discrete histograms is cheap; on embeddings people use kNN or kernel estimators and they are noisy at agent scale. Cross-entropy loss is exactly expected -log q_θ(y|x); minimizing it is MLE of the predictive model, and H(P)+D_KL(P||Q) so CE = irreducible noise + how wrong Q is.

Hermes mappings. Treat tokens as the rate currency and task success as the relevant Y. Do not compute Shannon quantities on 170 skills and hope; use the inequalities as design constraints.

1. Context compression. Structure: history X, compressor Z=f(X), downstream action A. Markov X→Z→A. DPI says I(X;A)≤I(Z;A) cannot hold unless Z retains task-relevant bits; I(X;A|Z) is irrecoverable loss. Rate-distortion: rate = tokens kept, distortion = task failure / unrecoverable facts (paths, safety wording, IDs). Naive: fill-ratio knobs (threshold 0.35, threshold_tokens 120k, micro-compact every N turns, prune old tool bodies). Uniform squeeze. Principled: type-dependent D — pin safety/procedural verbatim (Compaction Cliff: safety rules die under repeated lossy summary), gist closed tool pages, never regenerate regex/SQL from a gist (breadcrumb + source_range). Query-agnostic attention eviction is the known R(D) failure: you discard before Y is known. Worth it: the taxonomy is worth implementing (per-type budgets, delayed compact until next user/tool query, recoverability spot-check). Fitting R(D) curves or estimating H(history) is overkill. Hermes already has the right knobs; the math says stop compressing by fill fraction and start compressing by expired relevance.

2. Skill selection. Structure: task T, skill library S, loaded subset L. You want L that maximizes I(L; success | T) at a token rate |L|. Naive: dump the whole index (~2.6k tokens/turn), or cosine(top-K) on short descriptions. Cosine is not mutual information; it confuses vocabulary overlap with predictive value (SkillRet: generic embeddings miss the query/jargon gap; body-hidden routing drops 31–44 pp). Principled: I(S_i; T) ≈ whether loading S_i changes the next action (Toolformer-style: skip if it cannot reduce H(action|context)). Marginal I given already-loaded skills (Shapley/greedy submodular) beats independent cosine when skills overlap. Negative triggers are a hard I=0 gate. Worth it: description/routing_signals hygiene, hierarchical scope then rank, just-in-time load (TTE), and a success-rate blend — yes. Estimating true I(S;T) from tiny logs — no; you need outcome labels you do not have. At 170 skills BM25+triggers is enough; learned MI routers pay off nearer 300+ with logged (task, skills, outcome) triples.

3. Memory promotion (l1-extract → l1-promote → Hindsight). Structure: observation O, keep/drop bit K, future query Q. Promote iff I(O;Q_future) is large relative to description length. This is MDL plus bottleneck: store Z with small I(O;Z) and large I(Z;Q). Naive: recency/utility/uniqueness 0/1 scores, L0 discard / L1 session-only / L2 durable, cosine>0.85 dedup. Principled: expected bits saved on future turns (does missing this force a re-ask?) minus storage and retrieval-noise cost. Uniqueness is anti-redundancy, i.e. D_KL(new || existing) not cosine. Core memory (~2200 chars) is a hard rate; only facts with I(fact; every-turn action) near H(fact) belong there. Worth it: the L0/L1/L2 gate and write-gate (relevance + novelty) already are the IB policy in discrete clothes. Do not fit β. Dual-gate dedup (cosine AND equivalence) is the one numeric upgrade that earns its keep. Logging promote/recall hit rate (Source Hit@k) beats any entropy estimator.

4. Model routing. Structure: task T, model M as a channel with capacity C_M (tool fidelity, long-context calibration, cost/latency) and noise. You choose M to keep rate of required reasoning below C_M at minimum cost. Naive: skill-encoded role table (Sonnet parent, Grok leaves, Haiku compress, Mistral classify, Sol adversarial). No per-call router; delegation.model is global. Principled: cascade — cheap channel first, escalate only the synthesis step if residual H(error) (Fano) is too high. TwinRouterBench: difficulty spikes mid-trace, so query-level routing under-serves. Worth it: keep the role table. A learned I(T;M*) router is overkill and currently unimplementable (no step-level QE). Cheap confidence/Fano proxy after synthesis (escalate if confidence <7 on decision steps only) is the one bit of theory that changes the design. Routing compression off Mistral was a channel-coding fact: that channel's support did not include the required messages (422), so C=0 for that use.

5. Token budget across steps. Structure: sequential rate allocation under Σ r_t ≤ R and distortion on final A. Naive: one global cap (128k/200k), width of all tool schemas every turn. Principled: water-filling — spend rate where dR/dD is steepest. Empirically width (schemas) dominates memory injection; dump-all-tools is the worst water-filling. Marginal-value stopping (next retrieval if Δ unique facts / cost < ε) is sequential IB. Worth it: enabled_toolsets per leaf, early stop on plateau, CoT scratchpad offload. Computing actual R(D) per step is overkill; the inequality "do not spend a token that cannot change the action" is the whole policy.

6. Multi-agent messages. Structure: parent state X, child message M, parent action A. Child is a channel; M is a compressed code. DPI: the parent cannot know more about the world than I(world; M). Interaction tax is rate wasted on peer transcripts that are not about A. Naive: return verbose traces; parent pastes them. Principled: MDL codes — one self-contained answer, independent verdicts, no nested summaries of summaries (each rewrite is a DPI hit plus ACE context collapse). Fano on the parent: if M drops a constraint, Pe on safety/IDs is bounded below. Worth it: output contracts and gist+pointer, yes. Information-theoretic consensus (Hermes swarm reducers) only if you have independent channels; correlated Grok leaves do not give independent bits, so majority vote is not I(X;votes) scaling.

When the math changes the design: use DPI, R(D) by content type, Fano as escalate/stop, MDL as promote/load, IB as "compress X for Y=next action." When it does not: numeric H/I/KL on traces without a defined alphabet and a defined Y. Those numbers will not beat the heuristics already in hygiene, memory-layer-gate, and the routing skill.
