PRIMER: RLHF Theory and Preference Learning


CORE CONCEPTS

Reinforcement Learning from Human Feedback (RLHF) learns a reward signal from human preferences rather than hand-coded objectives. The canonical pipeline: collect pairwise comparisons (y_w preferred over y_l given prompt x), fit a reward model r(x,y), then optimise a policy π via RL (typically PPO) to maximise E[r(x,π(x))] subject to a KL penalty against a reference policy π_ref.

The Bradley-Terry model is the standard MLE framework for pairwise preferences. It posits P(y_w > y_l | x) = σ(r(x,y_w) - r(x,y_l)), where σ is the logistic function. Given a dataset D of (x, y_w, y_l) triples, the reward model is fit by minimising the negative log-likelihood: L = -E_D[log σ(r(x,y_w) - r(x,y_l))]. This is consistent and sample-efficient under the assumption that preferences are generated by a latent scalar reward plus logistic noise.

Direct Preference Optimisation (DPO, Rafailov et al. 2023) eliminates the explicit reward model entirely. It reparameterises the reward as r(x,y) = β log(π(y|x)/π_ref(y|x)) + β log Z(x), substitutes into the Bradley-Terry objective, and shows that optimising the policy directly on preference data minimises the same KL-constrained RL objective. The DPO loss is: L_DPO = -E_D[log σ(β log(π(y_w|x)/π_ref(y_w|x)) - β log(π(y_l|x)/π_ref(y_l|x)))]. No reward model training, no PPO, just supervised learning on preference pairs.

Goodhart's Law in RL: when r_hat (the proxy reward) diverges from r* (the true reward), optimising hard against r_hat produces policies that score high on r_hat while degrading on r*. Formally, KL(π || π_ref) growing without bound guarantees eventual reward hacking unless r_hat = r* almost everywhere. The practical corollary: reward model generalisation determines the safe optimisation budget. RLAIF (Constitutional AI / AI feedback) replaces human annotators with a model, scaling preference data but introducing a distribution shift from model-vs-human preferences.


COMPONENT ANALYSIS


User Correction as Preference Signal

(a) Structure. Each user correction is an implicit pairwise comparison: the corrected output y_l was rejected; the correction or ideal y_w is preferred. Formally, corrections populate D = {(x_t, y_w, y_l)} where x_t is the conversation context at turn t. The Bradley-Terry MLE applies directly. The key quantity is the margin: r(x,y_w) - r(x,y_l), which should be large when corrections are sharp and small when corrections are stylistic.

(b) Current Hermes. Corrections are occasionally surfaced via the l1-extract pipeline as raw session facts. There is no explicit preference pair collection, no reward model, and no mechanism to update skill routing or model selection based on correction history. Corrections influence memory narratively, not structurally.

(c) Principled approach. Log every user correction as a (context, rejected, accepted) triple. Train or fine-tune a lightweight Bradley-Terry scorer: r_theta(x,y) = MLP over embeddings. Use this scorer to re-rank candidate skill triggers and model routing decisions: choose skill s* = argmax_s r_theta(context, output_under_s). At minimum, apply DPO-style preference weighting to skill selection without a separate reward head: weight skill s by exp(β * correction_frequency(s)) / Z.

(d) Value assessment. Medium-high value if correction rate is non-trivial (>5% of turns). Main risk: correction signal is sparse and noisy in a routing system; the preference dataset accumulates slowly. Validate by checking whether correction-heavy skills show measurable output quality differences on held-out prompts. Requires structured logging (not yet present) before anything else.


Adversarial-Review as Implicit Reward Model

(a) Structure. Adversarial-review runs a second model M_adv over a proposed change and returns an accept/reject or critique. This is exactly a reward model: r_adv(x, y) in {0,1} or a scalar quality score. Under Bradley-Terry, two outputs compared by M_adv generate a pairwise preference. If M_adv is consistent, it approximates r* on the distribution of Hermes outputs.

(b) Current Hermes. Adversarial-review is triggered manually or by skill rule. The verdict is consumed as text; there is no numerical score, no history of verdicts, and no feedback loop to the model routing or skill selection that produced the reviewed output.

(c) Principled approach. Extract a scalar score from each adversarial-review invocation. Log (prompt, output, score) tuples. Fit a lightweight reward head r_theta over the embedding of (prompt, output) pairs, using review verdicts as labels. Use r_theta to gate tool calls and delegate_task outputs without re-running the full adversarial model each time: approve output y if r_theta(x,y) > tau, else escalate to full review. Tune tau via precision-recall on held-out review verdicts.

(d) Value. High value at current Hermes scale: adversarial-review is expensive (extra LLM call); a distilled reward head could cut invocation cost by 10-50x while preserving most of the safety signal. Risk is reward model generalisation: the distilled head may miss novel failure modes M_adv would catch. Validate by checking agreement rate between r_theta and M_adv on a 100-sample holdout. Worth implementing if agreement > 85%.


Skill Scoring from User Feedback

(a) Structure. Skills are policies: given context x, skill s produces output distribution π_s(y|x). Skillopt currently scores skills via a quality function Q(s). Under RLHF framing, Q(s) should be E_{x,y ~ π_s}[r*(x,y)], estimated from user feedback signals. Each piece of positive/negative feedback is a sample from r*(x, π_s(x)).

(b) Current Hermes. Skillopt uses heuristic quality scores (length, structure, edit frequency) plus GEPA genetic search over skill text. Feedback from users is not systematically tied to per-skill quality estimates; GEPA fitness functions are not grounded in preference data.

(c) Principled approach. Define Q_hat(s) = (1/N_s) * sum_{t: skill_s_used} r_hat(x_t, y_t), where r_hat is the adversarial-review reward head or a simple thumbs-up/down count. Use Q_hat as the GEPA fitness function instead of structural proxies. Apply an upper confidence bound: UCB(s) = Q_hat(s) + sqrt(log(T)/N_s) to balance exploitation of high-scoring skills with exploration of undersampled ones. This is a multi-armed bandit over the skill library with preference-grounded rewards.

(d) Value. Medium value. The bandit framing is well-understood and low implementation cost. The risk is Goodhart's Law: if Q_hat is based on adversarial-review scores, GEPA will optimise skill text to score well on the reviewer, not to actually help users. Mitigate by using diverse reward signals (review score + user correction rate + task completion rate). Validate by A/B testing GEPA runs with and without preference-grounded fitness on 10 skills.


Avoiding Goodhart's Law in Skillopt

(a) Structure. Goodhart's Law formalises as: if KL(π_optimised || π_ref) grows, r_hat(x, π_optimised(x)) diverges from r*(x, π_optimised(x)). In GEPA terms: as genetic search pressure increases over more generations, the optimised skill text drifts toward gaming whatever proxy Q_hat measures.

(b) Current Hermes. No explicit Goodhart mitigation. GEPA runs until a fitness plateau; there is no KL-style penalty on how far optimised skills drift from their originals, and no holdout evaluation on out-of-distribution prompts.

(c) Principled approach. Add a KL-regularisation term to the GEPA fitness: F(s) = Q_hat(s) - lambda * D(s, s_ref), where D(s, s_ref) is edit distance or embedding cosine distance from the original skill. Anneal lambda downward only when holdout performance is verified. Apply early stopping: halt GEPA when Q_hat gains on in-distribution prompts but drops on a held-out OOD prompt set. This is exactly the RLHF KL penalty applied to skill evolution rather than token generation.

(d) Value. High value, low cost. KL regularisation on GEPA requires one extra term in the fitness function and a small holdout set. Without it, GEPA optimises toward the reviewer's blind spots. This is the single highest-leverage theoretically-grounded change available given Hermes's current architecture.


IMPLEMENTATION CANDIDATES RANKED

1. KL-regularised GEPA fitness. Add embedding-distance penalty from original skill to GEPA fitness function; evaluate candidates on a 20-prompt OOD holdout. Expected benefit: prevents skill optimisation from drifting into reviewer-gaming, directly addressing the most concrete Goodhart risk in Hermes. Implementation cost: one fitness function edit, one holdout dataset, two hours.

2. Adversarial-review reward head distillation. Cache all adversarial-review verdicts with numerical scores; train a small MLP or logistic classifier over output embeddings to predict verdict. Expected benefit: 10-50x reduction in adversarial-review invocation cost while maintaining 85%+ agreement with full review. Implementation cost: 100+ verdict samples needed first, then a half-day of fitting and threshold calibration.

3. Structured correction logging as preference pairs. Add a thin logging layer that writes (context, rejected_output, correction) triples to a preference dataset file on every user edit or explicit negative signal. Expected benefit: creates the data foundation for every other preference-learning component; currently this data is lost. Implementation cost: one session-hook addition, negligible compute, high long-term leverage.
