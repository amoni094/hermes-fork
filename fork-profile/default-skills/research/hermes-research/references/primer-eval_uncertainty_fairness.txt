PRIMER: Uncertainty Quantification, Active Learning, and Algorithmic Fairness

CORE CONCEPTS

Uncertainty quantification (UQ) distinguishes two orthogonal sources of model error. Aleatoric uncertainty is irreducible noise inherent in the data-generating process — no additional data eliminates it. Epistemic uncertainty reflects gaps in model knowledge and shrinks with more data. Formally, for a Bayesian model p(y|x,w) with prior p(w), epistemic uncertainty is the variance of the predictive mean across the posterior p(w|D), while aleatoric is the expected variance of p(y|x,w) under that same posterior.

Calibration: a classifier is calibrated if P(Y=y | f(x)=p) = p for all p in [0,1]. The canonical fix is temperature scaling: replace logits z with z/T, where T is fit by minimising negative log-likelihood on a held-out set. This is a single scalar with a convex objective, making it cheap and effective. Expected Calibration Error (ECE) partitions confidence into M bins and computes a weighted absolute deviation between mean confidence and accuracy per bin.

Conformal prediction gives distribution-free coverage guarantees. Given a nonconformity score s(x,y) (e.g. 1 - f_y(x)) and a calibration set of size n, the prediction set C(x) = {y : s(x,y) <= q} where q is the (1-alpha)(1 + 1/n) quantile of calibration scores satisfies P(Y in C(X)) >= 1 - alpha exactly, under exchangeability. No distributional assumptions beyond exchangeability are required.

Active learning addresses label-efficient learning. Uncertainty sampling selects x* = argmax H[Y|x, D], where H is predictive entropy. For noiseless binary classification with a consistent hypothesis class, this is near-optimal: it achieves O(log |H|) label complexity versus O(|H|) for passive learning (Dasgupta 2005). Query by committee (QBC) maintains a hypothesis committee and queries points of maximum disagreement, approximating the version-space bisection optimal strategy.

Algorithmic fairness defines constraints across demographic groups. Demographic parity: P(Yhat=1|A=0) = P(Yhat=1|A=1). Equalized odds additionally requires equal true positive and false positive rates across groups. Calibration across groups (multi-calibration) is strictly stronger: P(Y=1|f(x)=p, A=a) = p for all groups a and all p. These constraints are generically in tension with each other (impossibility results apply when base rates differ across groups).


COMPONENT 1: Agent Uncertainty Estimation — When to Ask vs Act

(a) Mathematical structure. This is a sequential decision problem under uncertainty. At each turn the agent holds a belief state B_t over possible world-states and action outcomes. The ask-vs-act decision is a binary action with asymmetric costs: acting on a wrong belief has some cost C_err, asking incurs a latency/token cost C_ask. The optimal policy is: act if max_a E[U(a)|B_t] - C_ask > threshold, else ask. Epistemic uncertainty in B_t governs this threshold.

(b) What Hermes currently does. Purely heuristic. The model generates text expressing hedged language ("I'm not sure", "let me check"), and tool calls like web_search or skill_view are issued when the model's generation path encounters uncertainty tokens. There is no explicit belief state, no calibrated probability, and no formal cost model.

(c) Principled approach. Maintain a calibrated confidence score c_t in [0,1] for the current action candidate. Apply temperature scaling to the model's token log-probabilities for the key decision token. Set a threshold tau derived from the cost ratio: tau = C_ask / (C_ask + C_err). If c_t < tau, issue a clarify call or a verification tool call; else act. For structured outputs, use conformal prediction: build a prediction set over possible next-actions using a calibration set of (context, correct-action) pairs; if |C(x)| > 1 (ambiguous set), ask. The conformal set gives a coverage guarantee: the correct action is in the set with probability >= 1 - alpha.

(d) Value assessment. Medium-high value. The calibration step (temperature scaling on log-probs) is a one-time offline fit requiring ~200 labelled (context, correct-action) pairs from session logs — Hermes has these in lifecycle.db. The conformal wrapper is about 20 lines of Python. Risk: log-prob extraction depends on the model API exposing logprobs; Claude Haiku does, but some routing targets do not, requiring fallback. Worth a spike.


COMPONENT 2: Calibrated Confidence in Skill Selection

(a) Mathematical structure. Skill selection is a multi-class classification: given context embedding x, predict skill label y in {1,...,120}. The classifier outputs a softmax distribution p(y|x). Calibration means the argmax confidence score reflects true accuracy. Current tag/trigger matching is a deterministic rule system, not a probabilistic classifier, so its "confidence" is binary.

(b) What Hermes currently does. Tag matching: each skill has trigger keywords; at load time the dispatcher scores overlap between the current task description and trigger strings. The top match is selected. No score is produced; ties are broken arbitrarily. No calibration, no uncertainty propagation.

(c) Principled approach. Train or prompt a lightweight classifier (e.g. a small embedding model + linear head, or few-shot prompted Mistral-small) to score each skill for the current task. Apply temperature scaling to the resulting logit vector using a calibration set drawn from session history (task -> skill-used -> outcome). Report ECE before and after scaling. At decision time: if max_k p_k(y=k|x) < tau_skill (e.g. 0.6), do not auto-load — surface top-3 candidates for explicit selection or load all three in parallel using delegate_task. This directly addresses the current failure mode where skill routing misses due to keyword mismatch.

(d) Value assessment. Highest practical value of the three components. The skill library is already scored via skillopt/GEPA; adding a calibrated soft classifier sits naturally on top of that infrastructure. Dataset construction is cheap: ~500 (task, selected-skill, success/fail) tuples from existing cron agent logs. Risk: adds latency per turn for the classifier call; mitigate by caching embedding of the context prefix. The fairness angle — ensuring skill selection does not degrade for rare task types — is worth checking via multi-calibration across task categories.


COMPONENT 3: Active Learning for Eval Selection

(a) Mathematical structure. Hermes has a population of possible evals (test cases, regression scenarios). Each eval i has an unknown signal value v_i (does this eval catch real bugs / skill gaps?). The problem is: given a budget of B evals to run per cron cycle, which B to select? This is a Bayesian experimental design problem: select evals that maximise expected information gain about the skill/model quality parameter theta. Information gain = KL[p(theta|D + eval_i) || p(theta|D)].

(b) What Hermes currently does. Evals are run on a fixed schedule or when explicitly triggered. Selection is round-robin or manual. No model of which evals are most informative given current agent behaviour.

(c) Principled approach. Maintain a Beta(alpha_i, beta_i) belief over the pass-rate of each eval i. At each cycle, select the B evals with highest epistemic uncertainty: argmax_i alpha_i*beta_i / ((alpha_i+beta_i)^2 * (alpha_i+beta_i+1)) — this is the variance of the Beta, equal to the uncertainty sampling criterion for Bernoulli bandits. After running, update the Beta parameters from the pass/fail outcome. This is Thompson sampling adapted to eval selection: cheap to implement, well-understood, and provably sublinear regret. QBC variant: run the same eval against two model routes and flag disagreements as high-signal, then prioritise those evals for deeper human review.

(d) Value assessment. Low implementation cost, medium value. Requires only a lightweight eval registry with (alpha, beta) pairs persisted to a JSON file, updated after each cron run. No model API dependency. Risk: eval population must be reasonably large (>50) for the bandit to outperform uniform sampling; below that, just run all evals. QBC disagreement flagging adds genuine value to the adversarial-review pipeline with near-zero extra cost.


RANKED IMPLEMENTATION CANDIDATES

1. Calibrated skill selection with temperature scaling and soft routing.
What: replace binary tag-match with a calibrated probabilistic classifier over the 120-skill library, gated by a confidence threshold.
Expected benefit: reduces skill misrouting errors, especially on novel or ambiguous tasks where keyword overlap is low.
Implementation cost: ~2 days — embed task descriptions, fit linear classifier on session logs, temperature-scale on held-out set, add fallback-to-top-3 logic.

2. Conformal prediction wrapper for ask-vs-act decisions.
What: wrap the action-selection step with a conformal prediction set built on calibration logs; ambiguous sets trigger a clarify call.
Expected benefit: provides a coverage-guaranteed mechanism for the agent to know when it genuinely does not know, reducing confident wrong actions.
Implementation cost: ~1 day if logprobs are available from the active model route; requires a calibration dataset of ~200 labelled turns from lifecycle.db.

3. Beta-bandit eval selection for cron eval scheduling.
What: maintain per-eval Beta pass-rate beliefs and select the highest-variance evals each cycle using uncertainty sampling.
Expected benefit: concentrates eval budget on the evals most likely to reveal regressions, improving signal per compute-minute.
Implementation cost: ~4 hours — a JSON registry, a Beta update function, and a scheduler hook in the cron eval script.
