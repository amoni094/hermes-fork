PRIMER: Multi-Agent Systems Theory

Queuing. Kendall M/M/1: Poisson arrivals rate λ, exponential service μ, one server. Utilization ρ=λ/μ. Mean sojourn (queue+service) W=1/(μ−λ). Latency is not linear in load — the last 10% of ρ costs more than the first 90%. M/M/k is k servers; Erlang-C is P(wait>0). Little's law L=λW holds for any stable G/G/k: jobs in system = arrival rate × time in system. Jackson networks: open M/M queues with probabilistic routing have product-form stationary law — each node is an independent M/M/k at its effective arrival rate. You can size a pipeline (cron → worker → merge) without solving the joint chain. Kingman (G/G/1): E[wait]≈(ρ/(1−ρ))·((c_a²+c_s²)/2)·(1/μ). High service variance (research agents, 3–18 min) needs slack even at modest ρ.

Scheduling. Makespan C_max = completion of the last job. Tardiness max(0,C_i−d_i). Preemption interrupts a running job. List scheduling: next ready job to the first free machine. Graham: on m identical machines, C ≤ (2−1/m) C* — never worse than 2× optimal, ~1.9× at m=10. For independent parallel work, C_max = max_i T_i; the straggler, not the mean, sets wall clock.

Distributed computing. Consensus: agree on one value despite faults. Crash vs Byzantine (arbitrary output). FLP (1985): in a fully asynchronous network, no deterministic protocol achieves consensus with even one crash. Timeouts are not a hack; they supply the missing synchrony. CAP: under partition, pick consistency or availability. Practical systems use quorums and partial synchrony. Classical BFT (PBFT) needs 3f+1 replicas to tolerate f liars.

Communication complexity. Bits that must cross a cut to compute f when inputs are split. Deterministic equality of n-bit strings is Ω(n); randomized with error is ~√n. If each worker already holds local evidence, ship the function of that evidence the reducer needs — not the transcript.

Use these results, not folklore: Little (inventory=rate×latency); Jackson (find the bottleneck node); Graham 2-approx (greedy dispatch will not beat ~2× offline); FLP (you cannot wait forever for all N children and still guarantee agreement); CAP (stalled SSE is a partition: wait unbounded or proceed partial).

Cron (27 jobs). (a) Not M/M/1 user traffic. Multi-class G/G/1: interval watchdogs (10m Firecrawl) plus crontab convoys (03:00 WAL, TTL, lattice). Observed 13m-late daily ticks are queueing delay from a serialized scheduler tick, not clock error. (b) Mix of no_agent scripts (correct: they skip the LLM server) and LLM jobs on one queue. tick.lock prevents duplicate ticks, not due-job convoy. S9: a job can exit 0 with no state change, or overlap the next period. (c) Separate classes. Short deterministic scripts are M/D/1 — keep ρ≪0.5 so lateness stays rare. Never let a 20-min LLM job block a 2s watchdog (priority, not FIFO). Stagger tandem memory jobs (extract → promote → Graphiti) as a Jackson line; three independent 220–240m timers collide by construction. If service > period, ρ>1 and the queue is unbounded — lengthen the period or cap runtime. (d) High value for class isolation and convoy stagger. Low value for fitting Poisson models: arrivals are designed. Little's check is the one to run: if many jobs are "in run" at once, periods are too short or concurrency is unbounded.

delegate_task. (a) Independent jobs on m workers, here max_concurrent_children=10, max_spawn_depth=1. Makespan ≥ max(max T_i, (1/m)Σ T_i); greedy ≤ (2−1/m) OPT. (b) Batch tasks=[...] ; parent is a barrier join. Children isolated; default leaves cannot re-delegate. Parent stall timeout must be ≥ longest child (research 12–18 min; 300s kills live workers). (c) Helps when tasks are independent, similar duration, and join work ≪ min T_i. Hurts when a straggler sets C_max; when two writers share a file (last-writer-wins / incoherent SKILL.md merges); when N packets + N summaries saturate the parent window; when extra agents are same-model clones (co-failure φ≈0.92 — not extra reliability). Prefer 3–5 scoped workers over filling 10. Speculative extras only if you can abort stragglers; children are effectively non-preemptible until stall. (d) The 2-approx and straggler bound change design now: cap fan-out by duration variance, not by the slot cap. Expect ~2–4× wall-clock on uneven research, sometimes negative if merge tokens dominate.

hermes-swarm-consensus. (a) A child can return confident garbage (Byzantine), not just crash. (b) ≥3 majority; 2 highest confidence; escalate if winner <0.6 or hard contradiction. Mitigations exist on paper: blind ballot, no submission-order tie-break, strip reasoning from the arbiter packet, diversity gate, verbalized sampling. This is a confidence-weighted vote plus timeout-to-arbiter, not BFT. Homogeneous panels are one opinion counted N times. The reducer is a parent-LLM procedure, not a program. (c) Quorum over independent evidence (paths, URLs), not agent_ids. Cap confidence of same-model siblings. Drop silent children (AP) rather than block (FLP). Do not write majority beliefs into shared memory without provenance — epistemic inertia is the lie surviving after the liar is gone. True PBFT is not worth it: children are not state-machine replicas. (d) High. Implementing a 5-line majority over JSON verdicts beats another prompt paragraph. Majority-of-clones is the design to stop.

Context packets. (a) Compute the child's output_contract from (objective, scope, constraints, live state). Communication complexity: only bits that change that output. (b) hermes-context-packet/v1 is already the right cut versus dumping the parent transcript: refs not bodies, 2000-token cap, AgentPrune before fan-out. Still common: fat current_state, inlined findings, full tool catalogs. Interaction tax: sharing full peer solutions collapses diversity in one round. (c) Ship objective, scope_paths, ≤5 primed facts, output schema. Everything else is on-demand I/O. For consensus, send verdict+confidence+evidence_refs only. Equality of "same bug?" needs a claim hash, not an essay. (d) Highest ROI of the five. Cost is linear in N × packet size. Over-communication is the default failure.

Fleet of 10. (a) Ten children plus parent share the provider API (external M/M/k), local CPU, and the parent's context (a single-server join). (b) This instance allows 10; docs default 3. Throughput of completed tasks can rise until the API or the join saturates. Per-task latency does not fall with N; batch sojourn is max T_i plus provider queueing. (c) Heavy traffic: delay ~1/(kμ−λ). Ten children against a rate-limited API is small k at the provider. ρ≈0.7 already feels slow; high c_s² (Kingman) needs more slack. Size batches for ρ≈0.5–0.7 at the bottleneck (usually the API, sometimes parent tokens), not to fill 10 slots. Admit-control at the parent: queue or refuse extra tasks instead of a 10-wide barrier. (d) Medium-high. Measuring λ, μ, ρ on delegation logs beats another orchestration skill. Genuine change: admission control, not "use all 10."

Theory that should change Hermes: class-based cron; tandem stagger; fan-out capped by straggler variance; reduce on evidence not clones; packets as the communication-minimal interface; admit-control before width 10. Theory that should not: Poisson cron, PBFT among LLM clones, CAP as a skip-verification card, majority-of-same-model as reliability.
