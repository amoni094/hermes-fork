PRIMER: Singular Learning Theory (SLT)

================================================================================
FIELD OVERVIEW
================================================================================

Singular Learning Theory is the mathematical study of how learning happens in statistical models whose parameter space has singularities—regions where the Fisher information matrix is rank-deficient or zero. Real neural networks are singular models: redundant parameters, symmetries, and hierarchical structure create manifolds of equivalent solutions. Classical learning theory (based on regular statistical models) breaks down here. SLT replaces it with Watanabe's free energy formula, which characterizes model complexity and generalization via the real log canonical threshold (RLCT). The RLCT measures the effective degrees of freedom in a singular model during learning; it controls both the Bayesian Information Criterion and the Kullback-Leibler divergence decay rate. Phase transitions—sudden jumps in learning behavior—emerge as data grows. Why this matters: it predicts when and why models transition from memorization to generalization, guides model selection without overfitting penalties, and explains why deep networks escape the curse of dimensionality.

================================================================================
KEY RESULTS
================================================================================

Watanabe's Free Energy Formula: The free energy F_n = -log p(data | model) / n approximates -log p(data | model params) / n with error O(log n / n). Precisely, F_n = n * KL divergence + lambda * log(n) / 2 + o(log n), where lambda is the RLCT.

Real Log Canonical Threshold (RLCT): For a model p(x|w) and true distribution q(x), RLCT lambda = inf{alpha : integral p(x|w)^alpha q(x)^(1-alpha) dx < infinity}. Equivalently, for analytic models, lambda = (volume of level set around optimal w) / log(1 / error rate). For a regular model, lambda = d/2 (half the parameter dimension). For singular models, lambda < d/2.

Widely Applicable Bayesian Information Criterion (WBIC): WBIC = -log p(data | MAP estimate) + lambda * log(n) / 2, where MAP is the maximum a posteriori estimate. WBIC approximates log model evidence to O(1) error and does not require integration over parameter space.

Empirical Phase Transitions: In neural networks, learning exhibits phase transitions: at certain data sizes n*, the test error, effective dimension, and RLCT all change discontinuously. These correspond to "symmetry breaking" where the model suddenly uses a qualitatively different representational structure.

Neural Networks are Singular: A neural network p(y|x,w) with hidden units, weight sharing, or ReLU activations has RLCT strictly less than d/2. The model class itself exhibits singularities even before fitting data.

================================================================================
STANDARD PRACTITIONER TOOLS
================================================================================

WBIC Computation: Calculate MAP estimate via SGD + L2 regularization, then compute WBIC = -log p(data | w_MAP) + (lambda_estimate) * log(n) / 2. Lambda is typically estimated empirically by fitting the asymptotic expansion to hold-out validation curves.

Phase Diagram Estimation: Plot effective dimension (via singular value decay of Hessian or Fisher trace) and test error against dataset size. Identify breakpoints where both change slope; these mark phase transitions.

Model Selection Loop: For candidate models, compute WBIC for each on a held-out validation set. Rank by WBIC (lower is better). No cross-validation penalty tuning needed.

Lambda Estimation Libraries: Watanabe's team released R packages; PyTorch users typically implement manual lambda fitting via empirical free energy curves or Hessian spectral analysis.

HERMES APPLICATIONS
================================================================================

COMPONENT 1: SKILL QUALITY SCORING (skillopt subsystem)

Mathematical Structure:
Each skill (procedure file) is a model class: given task input, the skill maps to output. The "truth" is successful task completion. Skill quality is measured by how well a test suite of past tasks (with known correct outputs) is fit by the skill, minus a complexity penalty. This is exactly a model selection problem. The skill exhibiting the lowest generalization error is the best fit, but complex skills (longer files, more branches) overfit. SLT says: use RLCT-informed penalties instead of crude BIC or cross-validation.

Current Approach (Hermes):
skillopt scores each skill as: (accuracy on test tasks) - (heuristic penalty for code length + branching factor). The penalty is hand-tuned constants. When two skills have similar accuracy, the shorter one wins. This is fragile and doesn't account for whether the skill is "using its capacity efficiently" (singular structure).

SLT Approach:
Treat each skill as a statistical model. Represent a skill's output distribution as p(correct output | input, skill parameters w). The parameters w are implicit: branch probabilities, hidden decision thresholds learned from past executions. Compute WBIC for each skill candidate on a held-out test set:

WBIC_skill = -log(accuracy on heldout) + lambda_skill * log(n_test) / 2

where lambda_skill is the RLCT of that skill's structure. For a procedural skill, lambda_skill can be approximated by the effective degrees of freedom: count the number of decision points, weighted by how frequently they are "active" (used in past executions). Rank skills by lowest WBIC. This automatically balances fit quality with structural complexity in a principled way.

Value Assessment:
Worth It? YES, medium effort, high confidence. The skill selection problem is finite and well-scoped. lambda estimation is straightforward because skills are small and you have execution logs.

Implementation Cost: ~2 weeks. You need to (1) log skill execution traces (decision path taken, inputs, outputs), (2) build a per-skill lambda estimator (count active branches, weight by frequency), (3) replace the hand-tuned penalty in skillopt with WBIC computation, (4) A/B test on a suite of task types.

Risk: The key assumption is that skill structure (code branches, decision trees) maps to statistical singular structure. If a skill's "parameters" are not actually learned (they're hardcoded), lambda may not capture complexity. Mitigation: validate on synthetic skills with known complexity before rolling out.

COMPONENT 2: MODEL ROUTING (selecting Claude/GPT/Grok/Mistral per subtask)

Mathematical Structure:
At each step of a ReAct loop, Hermes must choose which model to call (budget constraint; each model has different latency/cost/capability). Each model class is a probability distribution over correct next actions/outputs. The "ground truth" is whether the action succeeds (downstream task completion signal, though delayed). This is Bayesian model selection with partial feedback.

Current Approach (Hermes):
Hard-coded heuristics: "use Claude for reasoning, GPT for factuality, Mistral for speed." Task type determines the router. No online learning; no feedback from outcomes to update router weights. Over time, routing is fixed even if ground truth (model capabilities) drifts or tasks evolve.

SLT Approach:
Maintain a running estimate of each model's RLCT on the current task distribution. As the system executes, collect outcomes (did the model's output lead to successful task completion?). Fit a lightweight Bayesian model for each (model, task type) pair:

p(success | model M, task T, prompt p) ~ Bernoulli(theta_M_T)

The "parameters" theta_M_T are learned online via Bayesian updates. The complexity of the model is its RLCT. For a simple Bernoulli model, lambda ≈ 0.5 (one effective parameter). But if you add structure (e.g., "Claude's success depends on prompt length" → add a feature), lambda increases.

Compute WBIC for the null hypothesis (all models equally good) vs. structured hypothesis (model-task-specific theta). Use the WBIC difference to decide whether to route to the highest-accuracy model or fall back to a safe default. As data accumulates, phase transitions occur: the model selection suddenly "resolves" to a clear winner.

Concretely, maintain a matrix M_scores[model][task_type] = WBIC(model on past task_type instances). When a new task of type T arrives, route to argmin(M_scores[:, T]). Update scores after task completion feedback arrives.

Value Assessment:
Worth It? YES, high value, medium effort, moderate confidence. Routing is a bottleneck and has real economic impact (cost per token, latency). SLT offers principled feedback integration.
