PRIMER: Logic, Semantics, and Knowledge Representation

CORE CONCEPTS

Logic provides formal languages for representing and reasoning about knowledge. First-order logic (FOL) extends propositional logic with quantifiers: a formula phi(x) with a free variable x is satisfied by an interpretation I under assignment g if I,g |= phi(x). FOL is semi-decidable: validity is not decidable, but unsatisfiability is enumerable. Description logics (DL) are decidable fragments of FOL used to build ontologies. The core DL ALC defines concepts via conjunction (C u D), disjunction (C t D), negation (~C), and role restrictions (existential: exists r.C, universal: forall r.C). The core theorem: ALC satisfiability is PSPACE-complete; SROIQ (the basis of OWL DL) is N2EXPTIME-complete but admits sound and complete tableau reasoners. An ontology is a pair T = (TBox, ABox): the TBox contains terminological axioms (class subsumptions, equivalences), the ABox contains assertions about individuals. Reasoning tasks include subsumption (is C subsumed by D in T?), instance checking (is individual a in class C?), and consistency. Modal logic adds operators: Box phi (necessarily phi) and Diamond phi (possibly phi), interpreted over Kripke structures (W, R, V) where W is a set of worlds, R a binary accessibility relation, and V an assignment. S4 (reflexive, transitive R) models knowledge; KD45 models belief. Non-monotonic reasoning handles defeasible inference: in default logic, a default d = alpha : beta / gamma fires if alpha is believed, beta is consistent with current beliefs, and gamma is then added. Answer set programming (ASP) computes stable models of logic programs with negation-as-failure: a set S is a stable model of program P if S is the minimal model of the GL reduct P^S. Probabilistic logic programming (ProbLog) assigns probabilities to ground facts; the probability of a query q is the sum of probabilities of proof explanations.

HERMES COMPONENT ANALYSIS

Knowledge Graph Semantics (Graphiti)

(a) Mathematical structure. Graphiti is a typed property graph G = (V, E, lambda, mu) where V are entity nodes, E are directed labeled edges (fact triples), lambda assigns types to nodes and edges, and mu assigns property maps. This is an instance-level ABox with implicit TBox. Edge labels are relation types (e.g., "works_at", "contradicts"); edge weights and timestamps give temporal and confidence metadata. The intended semantics is closest to a DL ABox over a schema-free TBox, with no closed-world assumption.

(b) Current behavior. Hermes populates Graphiti via l1-extract by heuristic NLP extraction: named entity recognition plus co-occurrence patterns generate triples. Retrieval is vector-similarity over node/edge embeddings. No consistency checking is performed; contradictory facts coexist silently.

(c) Principled approach. Attach a lightweight DL TBox to the schema: define entity classes (Person, Project, Tool) and role restrictions (e.g., "author" range: Person). Run ABox consistency checking using a tableau algorithm at ingest time. Contradiction detection: if adding triple (a, r, b) makes the ABox inconsistent with the TBox, flag and route to resolution. Belief revision (AGM theory): for an inconsistent ABox A and new assertion phi, the revised set A * phi = (A - perp(A, phi)) union {phi} where perp selects a maximal consistent subset. This gives a principled forgetting operator for stale or conflicting facts.

(d) Value assessment. Medium. The practical gain is catching silent contradictions before they propagate to agent decisions. Risk: tableau reasoning over a large ABox is expensive; mitigation is to use a lightweight EL profile (polynomial reasoning) rather than full OWL DL. Validate by injecting known contradictions and checking detection rate before committing to production.

Skill Ontology

(a) Mathematical structure. The skill library is a set S of ~120 procedural documents. Each skill has a trigger string and category. This is implicitly a partial order: skill A specialises skill B if A's applicability conditions entail B's. Formally: define a concept language over skill attributes (task type, tool set, output contract); subsumption C_A |= C_B holds when every scenario satisfying A's trigger also satisfies B's.

(b) Current behavior. Routing is tag/keyword matching against skill descriptions: the trigger prefix (first 57 chars) is the primary signal. No subsumption inference; if a more specific skill exists but its tag doesn't match, the generic skill is loaded instead.

(c) Principled approach. Represent each skill as a DL concept defined over attributes: domain (code, research, ops), tool_set (subset of available tools), output_type, preconditions. Build a TBox with named subsumptions: github-issue-to-pr SubClassOf github-operations. At routing time, compute the most specific applicable concept given the current task description classified against the TBox. This is standard DL instance classification: given task t, find all C such that t is-a C in T, then return the most specific (leaf) node. Cost: O(|S|^2) subsumption checks to build the hierarchy; amortised at startup.

(d) Value assessment. High. Misrouted skills are a known failure mode (the skill trigger system is explicitly noted as approximate). A DL-backed hierarchy eliminates redundant skill loads and catches gaps. Risk: encoding 120 skills in a concept language requires manual annotation effort, perhaps 2-3 hours. Validate by measuring skill-routing precision on a held-out set of 50 task descriptions before and after.

Agent Belief Representation

(a) Mathematical structure. An agent's beliefs at turn t are implicitly the set of sentences derivable from: the system prompt, compressed conversation history, loaded skill content, and tool results. This is a classical belief set closed under logical consequence. Modal logic gives a cleaner account: define a Kripke model (W, R_K, R_B, V) where R_K is an accessibility relation for knowledge (S4: reflexive, transitive) and R_B for belief (KD45: serial, transitive, Euclidean). The agent believes phi at world w iff phi holds at all worlds accessible via R_B from w.

(b) Current behavior. Hermes has no explicit belief state. Context compression summarises history, which is a lossy projection. There is no tracking of which facts are believed versus known versus uncertain. The agent may contradict itself across turns when compression discards relevant history.

(c) Principled approach. Maintain a minimal explicit belief base B as a set of weighted propositions (phi, confidence). On each turn, update B using a Jeffrey conditionalization rule: P'(phi) = P(phi | e) * P(e) + P(phi | ~e) * P(~e) where e is the new evidence from the current tool result. Flag contradictions (phi in B and ~phi inferred from new evidence) and route to the adversarial-review skill before proceeding. This is tractable if B is kept small (key facts only, not full conversation).

(d) Value assessment. Low-to-medium near-term. Full Bayesian belief tracking across turns is expensive and brittle with LLM-generated confidence scores. The practical near-term win is narrower: flag explicit self-contradiction (same entity, opposing predicates within the same session) using a simple inconsistency check. Validate by constructing adversarial sessions where the agent is fed contradictory tool results and measuring whether contradiction is surfaced.

Memory Consistency Reasoning

(a) Mathematical structure. The memory pipeline (l1-extract, l1-promote, hindsight) produces a knowledge base KB = {(phi_i, t_i, s_i)} where phi_i is a proposition, t_i a timestamp, and s_i a confidence score. Temporal consistency requires that for any pair phi, ~phi: the higher-scored, more recent fact dominates. This is a prioritised default logic: defaults are defeasible assertions ordered by priority (recency x confidence).

(b) Current behavior. l1-promote applies threshold scoring with TTL decay. No cross-fact consistency check. Hindsight retrieval returns top-k by embedding similarity regardless of mutual consistency.

(c) Principled approach. Apply a prioritised ASP program at retrieval time. Encode each memory fact as a defeasible rule: holds(phi, T, S) :- memory(phi, T, S), not defeated(phi). A fact is defeated if a higher-priority contradicting fact exists: defeated(phi) :- memory(~phi, T2, S2), T2 > T1, S2 >= S1. The ASP stable model yields a consistent subset of KB for the current query. This is incremental and cheap for small retrieval windows (top-20 candidates).

(d) Value assessment. High. Stale contradictory memories are the most concrete failure mode: the agent is told X is true in session 1, X becomes false in session 2, and the old fact resurfaces. The ASP consistency filter is implementable in under 100 lines using clingo (available via pip). Validate by measuring retrieval precision on a curated set of temporal override pairs.

RANKED IMPLEMENTATION CANDIDATES

1. ASP-based memory consistency filter. Runs clingo over top-k hindsight candidates at retrieval time to remove contradicted facts. Expected to eliminate stale-fact hallucination, which is the highest-frequency knowledge error in long-running Hermes sessions. Cost: ~100 lines of Python wrapping clingo, one afternoon.

2. DL-backed skill subsumption hierarchy. Annotate 120 skills with a 5-attribute concept language; compute subsumption at startup; route to most-specific applicable skill. Expected to reduce skill mismatch and redundant multi-skill loads. Cost: 2-3 hours of skill annotation plus a 50-task routing eval.

3. ABox contradiction detection at Graphiti ingest. Attach a lightweight EL TBox to the graph schema; check each new triple for class-level inconsistency before insertion. Expected to surface conflicting entity facts before they silently corrupt downstream reasoning. Cost: medium (requires schema formalisation and EL reasoner integration, roughly one day).
