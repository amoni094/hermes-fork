PRIMER: Numerical Optimization Theory

Numerical optimization seeks x* = argmin f(x) over a domain, where f is the objective. Core concepts: gradient descent (GD) updates x_{t+1} = x_t - eta * grad_f(x_t); convergence depends on f's smoothness (L-smooth: grad f is L-Lipschitz) and strong convexity (mu-strongly convex: f >= quadratic lower bound). For L-smooth convex f, GD converges at O(1/t) on function value gap; for mu-strongly convex f, at linear rate O(rho^t) where rho = 1 - mu/L < 1, the condition number kappa = L/mu governs speed. Newton's method uses the Hessian H = grad^2 f: x_{t+1} = x_t - H^{-1} * grad_f(x_t), converging quadratically near the optimum but costing O(n^3) per step. L-BFGS approximates H^{-1} using m recent gradient/iterate pairs, achieving superlinear convergence at O(mn) cost. SGD replaces the full gradient with a noisy mini-batch estimate g_t, trading convergence rate for per-step cost; for convex f, SGD converges O(1/sqrt(t)). Adam maintains per-parameter first moment m_t = beta1*m_{t-1} + (1-beta1)*g_t and second moment v_t = beta2*v_{t-1} + (1-beta2)*g_t^2, updating x_{t+1} = x_t - eta * m_t_hat / (sqrt(v_t_hat) + eps), effectively normalizing the gradient by its recent RMS. Warmup + cosine decay: eta(t) = eta_max * 0.5 * (1 + cos(pi * t / T)) after a linear warmup phase, empirically robust across architectures. Trust region methods constrain each step to a ball: min m(x+p) s.t. ||p|| <= delta, replacing the global quadratic assumption of Newton with a local one and rejecting steps that don't reduce f sufficiently.


COMPONENT 1: Skill Scoring Optimisation (GEPA/SkillOpt)

(a) Mathematical structure. A skill s_i is a point in a discrete combinatorial space S (the set of possible SKILL.md texts). The objective is a noisy quality function q: S -> R (e.g., eval pass rate, task completion, human preference score). GEPA treats this as a genetic algorithm over S: crossover and mutation operators explore neighbors of high-scoring skills; the Pareto front balances multiple objectives (quality vs. brevity). This is a black-box, zeroth-order optimization problem since no gradient of q w.r.t. s_i is available.

(b) What Hermes does. SkillOpt scores skills by counting usage, success signals, and heuristic tag-match accuracy. GEPA mutates skill text and re-evaluates on a fixed sample. Selection is tournament-style; there is no convergence criterion or adaptive step size. The population size and mutation rate are fixed hyperparameters.

(c) Principled approach. Model q as a Gaussian Process (GP): q(s) ~ GP(mu(s), k(s,s')). Run Bayesian Optimization (BO): at each iteration, select s* = argmax EI(s) where EI is the Expected Improvement acquisition function over the GP posterior. This adapts the search to the uncertainty landscape, concentrating evaluations where improvement is most likely. For the genetic component, use a covariance-adaptive CMA-ES in the embedding space of skills (embed each skill with a fixed encoder, optimize in R^d, decode back). CMA-ES maintains a full covariance matrix C of the search distribution, updating it as C_{t+1} = (1-c1-cmu)*C_t + c1*rank-1 update + cmu*rank-mu update, enabling superlinear scaling of search efficiency.

(d) Value assessment. BO is worth implementing for the outermost skill selection loop (which skill variant to evaluate next) because eval budget is small (dozens, not thousands). CMA-ES is worth it only if you embed skills in a continuous space and have a differentiable proxy scorer. Risk: GP posterior becomes unreliable if the skill embedding space is poorly structured. Validate by running BO vs. current GEPA on a 20-skill eval set and measuring wall-clock improvement per evaluation.


COMPONENT 2: Convergence of Iterative Agent Refinement

(a) Mathematical structure. Each Hermes refinement loop (ralph-loops, adversarial review, cron agent rewrites) is a fixed-point iteration: x_{t+1} = F(x_t), where x is the agent state (skill set, memory, routing weights) and F is the refinement operator (LLM critique + apply). Convergence to a fixed point x* requires ||F(x) - F(y)|| <= rho * ||x - y|| for rho < 1 (Banach contraction). The convergence rate is geometric: ||x_t - x*|| <= rho^t * ||x_0 - x*||.

(b) What Hermes does. ralph-loops run for a fixed iteration cap with no convergence check. The adversarial review skill fires once per change, not iteratively. There is no measurement of ||x_t - x_{t-1}|| across turns to detect stalling or cycling.

(c) Principled approach. After each refinement step, compute a delta metric: delta_t = score(x_t) - score(x_{t-1}). Fit a geometric model to the delta sequence: delta_t ~= C * rho^t. Terminate when delta_t < epsilon (absolute tolerance) or when the estimated rho >= 1 (divergence detected, abort). For adversarial review, run two agents as a Richardson extrapolation: x* ~= x_t + (x_t - x_{t-1}) / (1 - rho_hat), where rho_hat is estimated from two consecutive deltas. This extrapolates toward the fixed point without additional LLM calls.

(d) Value assessment. The convergence check is low-cost and immediately reduces wasted iterations in ralph-loops. Richardson extrapolation is speculative (requires a good rho estimate) but could cut adversarial review rounds from 3 to 1 with acceptable accuracy loss. Validate by logging delta_t across 10 ralph-loop runs and checking whether a geometric fit holds (R^2 > 0.9). Risk: if F is non-contractive (rho >= 1), the system oscillates; the abort condition catches this.


COMPONENT 3: Second-Order Optimisation for Routing Decisions

(a) Mathematical structure. Model routing is a policy pi: context c -> model m, optimized to minimize expected cost E[cost(m, c)] subject to quality constraints E[quality(m, c)] >= Q_min. If cost and quality are differentiable functions of a routing weight vector w (e.g., softmax weights over model set M), this is a constrained optimization problem. The Hessian H = grad^2 L(w) captures curvature of the cost landscape; Newton's step w_{t+1} = w_t - H^{-1} * grad L(w) converges faster near the optimum than gradient-only methods.

(b) What Hermes does. Model routing uses a rule table in config.yaml: task type -> model, with manual thresholds updated by the user. There is no online learning, no Hessian, and no feedback loop from actual task outcomes into routing weights.

(c) Principled approach. Maintain a routing weight vector w in R^|M|. After each task, observe (cost_actual, quality_actual). Update w via online L-BFGS: accumulate (grad_t, delta_w_t) pairs; at each update, apply the two-loop L-BFGS recursion to compute H^{-1} * grad without storing the full Hessian. Constrain quality via a log-barrier: L(w) = cost(w) - lambda * log(quality(w) - Q_min). The effective routing decision is pi(c) = softmax(w)_argmax, updated every N tasks. An alternative with no gradient: use Thompson Sampling over a Beta-Bernoulli bandit per model, which achieves O(sqrt(T log |M|)) regret without any second-order structure.

(d) Value assessment. L-BFGS routing requires reliable scalar cost and quality signals per task, which Hermes does not currently instrument. Thompson Sampling is implementable now using existing task success/failure logs and converges to near-optimal routing in O(|M| * log T) tasks. Risk of L-BFGS: gradient estimates from LLM quality scores are noisy; use a Polyak-averaged gradient to reduce variance. Validate Thompson Sampling by A/B testing against current rule table on 50 routing decisions logged in the cron pipeline.


RANKED IMPLEMENTATION CANDIDATES

1. Thompson Sampling for model routing. A Bayesian bandit that updates a Beta(alpha_m, beta_m) posterior per model from observed task outcomes and samples routing decisions proportionally. Expected benefit: removes manual routing table maintenance and converges to the cheapest model meeting quality thresholds within O(|M| log T) tasks. Implementation cost: two counters per model per task type, updated post-task; fits in a 50-line Python module reading existing cron logs.

2. GP-Bayesian Optimization loop for SkillOpt. Replace fixed-mutation GEPA with a GP surrogate over skill embedding coordinates, using Expected Improvement to select the next skill variant to evaluate. Expected benefit: cuts eval budget by roughly half compared to blind genetic search by concentrating evaluations near the current optimum. Implementation cost: requires a fixed skill encoder (e.g., sentence-transformers running locally), a GP library (scikit-learn GaussianProcessRegressor), and a 30-evaluation pilot on a held-out skill set.

3. Delta-convergence termination for ralph-loops. After each iteration, compute a quality delta from the existing SkillOpt scorer; fit a two-point geometric model; terminate when delta < epsilon or rho >= 1. Expected benefit: eliminates wasted LLM calls in loops that have already converged, reducing per-run cost by an estimated 30-50% on already-good skills. Implementation cost: five lines of Python in the ralph-loop harness, zero new dependencies.
