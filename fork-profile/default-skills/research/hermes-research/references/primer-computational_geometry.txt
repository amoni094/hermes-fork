PRIMER: Computational Geometry

------

FIELD OVERVIEW

Computational Geometry studies algorithms for computing with geometric objects: points, lines, polygons, polytopes in Euclidean space. Core objects are convex hulls (minimal enclosing convex sets), Voronoi diagrams (space partitions by proximity), Delaunay triangulations (dual to Voronoi, maximizes minimum angles), and range trees (spatial indexing for fast queries). Why it matters: these structures solve proximity and ordering problems in d-dimensional space with worst-case guarantees. Most problems have trivial O(n²) brute-force solutions; Computational Geometry provides O(n log n) or O(n log^d n) algorithms with tight lower bounds. It's the mathematical foundation for nearest-neighbor search, collision detection, spatial databases, and geometric optimization. Unlike numerical methods, these algorithms are combinatorial—correctness doesn't degrade with floating-point error in carefully implemented versions.

KEY RESULTS

Convex Hull (Graham Scan, Quickhull): Given n points in d dimensions, find minimal convex set containing all. 2D: O(n log n) deterministic, O(n) expected after sorting. 3D: O(n log n) via incremental insertion or divide-and-conquer. Lower bound: Omega(n log n) in 2D (reduces to sorting).

Voronoi Diagram: Partition space into regions where each region contains all points closer to one seed point than any other. O(n log n) construction in 2D via plane sweep or divide-and-conquer. Dual: Delaunay triangulation. Property: For any Delaunay simplex, the circumsphere contains no other points. Used in nearest-neighbor by walking Delaunay graph in O(n) worst case, O(log n) average with good triangulation.

Approximate Nearest Neighbor (ANN): Exact NN is Omega(n) per query in high dimensions (curse of dimensionality). Approximation: (1+epsilon)-NN returns point p such that dist(q,p) <= (1+epsilon)*dist(q, true NN). Locality-Sensitive Hashing (LSH): hash points so that nearby points collide with probability > 1-delta. Query time O(n^rho) where rho < 1 depending on approximation ratio. Random projection trees: recursively partition space by random hyperplane, giving O(log n) depth, O(n^{1/(1+eps)} * log n) query time for (1+eps)-ANN.

Range Trees: Nested trees indexing d dimensions. Query [a1,b1] x [a2,b2] x ... x [ad,bd] in O(log^d n + k) time where k = output size. Space O(n log^{d-1} n). Fractional cascading reduces query to O(log n + k).

STANDARD PRACTITIONER TOOLS

Libraries: CGAL (C++, production-grade), Scipy.spatial (Python KDTree, ConvexHull, Voronoi), Shapely (2D polygons), Boost.Geometry. Algorithms to code: KDtrees (recursive bisection), ball trees (hierarchical balls), Quickhull (simpler than Graham in practice), sweep line (events + status structure). Formulas: cross product for orientation (det), dot product for projection, Gram-Schmidt for orthogonal basis. Most practitioners use spatial indexes rather than constructing Voronoi explicitly. High-dimensional NN defaults to LSH or random projections, not exact Voronoi.

HERMES APPLICATIONS

Application 1: Embedding-Space Skill Retrieval

Mathematical Structure: Skill embeddings live in high-dimensional vector space (e.g., 1536D from OpenAI). Retrieving "nearest K skills by relevance" is d-dimensional nearest neighbor search. Current context window forces max ~50 skills in L1 cache. Problem: find top-K most similar to query embedding in O(log n) per turn, not O(n).

Current Hermes Approach: Linear scan over all loaded skills, compute cosine similarity to query embedding, sort. O(n*d) per turn where n = skill count, d = embedding dimension. For ~100 skills this is acceptable; at 1000 it becomes bottleneck.

Principled Approach: Build a Hierarchical Navigable Small World (HNSW) graph on skill embeddings at startup. HNSW is approximate nearest-neighbor index: each node connects to ~16-64 nearby neighbors across log(n) layers. Query: start at top layer, greedily walk toward query, descend layers. Guarantees (1+epsilon)-ANN in O(log n) distance computations, O(1) memory per edge. Alternatively: random projection tree for 1536D → log(1000) ≈ 10 tree depth, O(log n) leaf search, then linear scan within leaf bucket (~10-20 skills). Both beat linear scan by 10-100x at 1000 skills.

Value Assessment: Worth it. HNSW is production-grade (Faiss, Annoy implement it). Spike: replace skill_retrieval with Faiss IndexHNSW. Risk: low. Math transfers perfectly—embedding distance already metric. Cost: ~2KB per skill for graph structure. Win threshold: >500 skills loaded, turns where skill selection is frequent.

Application 2: Geometric Clustering of Research Papers

Mathematical Structure: Research papers have embeddings (1536D). Hypothesis: papers cluster in embedding space; clusters correspond to research topics. Voronoi diagram partitions embedding space; each seed is a cluster center. Cluster membership is all points in that Voronoi cell. Delaunay adjacency tells which clusters are close.

Current Hermes Approach: K-means clustering on paper embeddings (deterministic if seeded). Assign papers to nearest centroid. Cluster identity stable if embeddings are static. No spatial index: each new paper compared to all K cluster centers.

Principled Approach: (1) Construct Voronoi diagram with cluster centroids as seeds. O(n log n) in 2D or 3D after dimensionality reduction (PCA to 3D loses minimal info in well-separated clusters). (2) For new paper p: find which Voronoi cell contains p, assign to that cell's cluster. Query via point location in Voronoi: O(log n) with balanced BSP. (3) Exploit Delaunay: if two clusters are Delaunay-adjacent, papers near their shared boundary may transfer knowledge—surface area = collaboration opportunity. (4) Incrementally update Voronoi as centroids shift (expensive in high D, feasible in 3D).

Value Assessment: Marginal. K-means already fast. Voronoi construction and point-location are overkill for cluster assignment if k is small (<50). Real value: Delaunay adjacency graph revealing which topics interact. Build it once per research sweep (cron-driven, not per-turn). Risk: Voronoi in 1536D is numerically unstable and slow; must reduce dimensions first. Cost: ~1 hour to code PCA + Voronoi construction. Worthwhile only if you want to reason about cluster structure, not just membership. Recommended: build 3D Voronoi on PCA projection as a visualization/analysis tool, not a production lookup.

Application 3: Spatial Indexing for Knowledge Graph

Mathematical Structure: Knowledge graph is directed acyclic graph of facts: (entity, relation, entity). Each fact has relevance score. Query: "retrieve all facts relevant to (agent_state, recent_context)." Embedding each fact into continuous space (e.g., TransE: entity1 + relation ≈ entity2 in embedding space). Problem: retrieve top-K facts in O(log n) not O(n).

Current Hermes Approach: Full scan of fact base, score each by embedding similarity to query, return top-K. Recomputed per hindsight promotion or long-term memory retrieval. O(n*d) per query.

Principled Approach: (1) Build range tree on fact embeddings to answer queries on axis-aligned hypercubes. Not directly applicable—queries are not rectangles but balls (find all facts within radius r of query point in embedding space). Better: (2) Build ball tree (recursive bisection by circles). Each internal node covers all facts in a ball; leaves store ~20 facts. Query: traverse tree, prune branches where ball doesn't intersect query sphere. Expected O(log n) node visits if query radius is small. (3) Alternative: LSH with cosine similarity. Hash each fact embedding to bucket (via random hyperplane). Query: hash query, retrieve bucket, scan bucket (~100 facts expected). Expected O(1) time if hash functions chosen well.
