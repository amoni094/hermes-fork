PRIMER: Reinforcement Learning Theory

An LLM agent loop is not an MDP solver. It is a prompted policy over tools. RL theory still names the objects you already have: states (workspace + memory), actions (tools), delayed outcomes, constraints, subtasks, and noisy evaluation. Use it to choose structures. Do not import algorithms whose assumptions (tabular S,A, stationary T, scalar r) Hermes does not satisfy.

CORE CONCEPTS

PAC-MDP (Kakade; Strehl et al.). An algorithm is PAC-MDP if, with probability ≥1−δ, after a number of samples polynomial in |S|, |A|, 1/ε, 1/δ, 1/(1−γ), it acts ε-optimally except on a polynomial number of steps. The object is sample complexity of exploration, not asymptotic convergence. The operational idea is “knownness”: a (s,a) is known after m visits, unknown otherwise.

RMAX (Brafman & Tennenholtz) is the canonical model-based PAC-MDP method. Maintain empirical T̂,R̂ on known pairs. Unknown pairs are assigned Rmax (optimism). Plan on that model (value iteration). When m is large enough, the model of known states is accurate and optimism forces exploration of the unknown. This is model-based RL: learn T and R, then plan. Model-free methods skip T; they need more samples and give weaker “when is the estimate reliable?” answers.

Constrained MDPs (Altman). Maximize E[∑ γ^t r] subject to E[∑ γ^t c_i] ≤ d_i. Safety is a feasible set, not a penalty you hope is large enough. Lyapunov safety (Chow et al.) is stricter: a function L on state such that one-step expected L decreases (or stays) outside a safe set, so the next state remains in a controlled invariant. CMDP constraints are in expectation over trajectories; Lyapunov/shielding is closer to pathwise set invariance.

Potential-based reward shaping (Ng, Harada, Russell 1999). Add F(s,a,s′)=γΦ(s′)−Φ(s). Then Q*_F(s,a)=Q*_r(s,a)+Φ(s), so argmax_a is unchanged. Any shaping that is not of this form can change the optimal policy (shortcut hacking). Φ is a function of state, not of documents or heuristic scores.

Options (Sutton, Precup, Singh). An option o=(I,π,β): initiation set, intra-option policy, termination β(s). The SMDP Bellman equation is Q(s,o)=E[r_{t:t+k}+γ^k max_{o′} Q(s_{t+k},o′)], k∼β. Intra-option form: Q(s,o)=r_o(s)+γ∑_{s′}P(s′|s,o)[(1−β(s′))Q(s′,o)+β(s′)max_{o′}Q(s′,o′)]. Hierarchy helps when options shorten effective horizon and are reused; bad options raise sample complexity (Dietterich; Jong).

Inverse RL. Given (near-)optimal trajectories, recover R such that the behavior is optimal. Ill-posed: many R share an optimal policy. MaxEnt IRL / occupancy matching pick a particular R. Needs coverage of expert behavior, not a handful of corrections.

KEY RESULTS (what you may actually use)

1. RMAX: if m = Θ̃(1/(ε²(1−γ)³) log(|S||A|/δ)), the algorithm is PAC-MDP. The number is huge for language-scale |S|. Keep the qualitative rule: do not treat a pair as known after one success.

2. CMDP Lagrangian: L(π,λ)=V^r(π)−∑λ_i(V^{c_i}(π)−d_i). A saddle (π*,λ*) is optimal under Slater (strict feasibility). Dual λ* is the shadow price of the constraint. If the constraint is hard (“never delete user data”), a finite λ is the wrong object: you want a shield, not a price.

3. PBRS policy invariance: only γΦ(s′)−Φ(s) preserves optima. Bonuses on “use this skill,” “higher skillopt score,” or “user said good job” are not PBRS unless rewritten as a potential on state.

4. Options Bellman: value of a subtask is reward accumulated until termination plus discounted continuation. Termination design is load-bearing: if β is late, credit is delayed; if β is early, the option never finishes the subgoal.

HERMES

Safe cron agents.
(a) Theory: CMDP = max task value s.t. E[cost]≤d; Lyapunov = stay in a safe set (backups exist, no pending irreversible, blast radius bounded). Shielding / ATP is a hard feasible-set projection, not a dual update.
(b) Current: deny-by-default, timeout=deny, scoped toolsets, ATP constraint set C on projected state, trajectory-risk prefix scoring, “propose don’t dispose.” This is constrained policy + invariant, not learned λ.
(c) RL would add dual ascent on costs, or a learned Lyapunov critic. That lets the agent buy safety violations when reward is high.
(d) Value: formulation high, learning low. Infra safety wants C as executable predicates (no delete without backup, no merge, no production). Lagrangian CMDP is actively harmful for “never.” Use Lyapunov-style state: irreversible_action_count, peak_risk_floor (LoopHarness) — these are already discrete Lyapunov coordinates. Do not train them.

Skill scoring as reward shaping.
(a) PBRS requires F=γΦ(s′)−Φ(s) on MDP state. Skillopt Q=0.35 success+0.25(1−correction)+0.20 freq+0.20 recency is a document/process metric. Using it as a bonus on “load skill X” changes the policy over options.
(b) Hermes scores SKILL.md structure and outcome logs; edits are bounded and human-gated. Scorer is heuristic, not a held-out return.
(c) To get invariance you would define Φ on task state (tests passing, files verified) and shape the agent’s step reward. Skill scores would at most initialize option priors, not r.
(d) Value: calling this “reward shaping” is a category error. It is prior/filter on procedural memory. Policy invariance is neither present nor wanted: you want low-quality skills to be used less. Keep scoring as admission/repair signal (low score ⇒ look), never as proof of quality. Pass^k already does the RL-valid part: estimate from outcomes, not from the proxy.

Hierarchical tasks / options.
(a) delegate_task is an option: I = “slice is independently verifiable,” π = child prompt+tools, β = DONE/FAILED/stall. SMDP theory: keep k short, terminate on a checkable predicate, reuse o across tasks. Over-deep nesting wrecks credit and context.
(b) Hermes: narrow child goals, isolated worktrees, verify before merge, stall-on-progress not wall-clock, enabled_toolsets as initiation/capability.
(c) Option-critic / MAXQ would learn I,β from returns. No stationary r, almost no repeated identical (s,o). Not trainable here.
(d) Value: design rules high, learning low. Write β as acceptance criteria before spawn; do not spawn if the slice is not an option (cannot terminate independently). That is the theory that pays.

Sample efficiency.
(a) PAC-MDP: knownness after m visits; m polynomial in 1/ε²(1−γ)³. For a Bernoulli success rate, Hoeffding: n≥(1/2ε²)ln(2/δ). ε=0.15, δ=0.05 ⇒ n≈134. Consecutive Pass^3 is a different statistic (run of successes), much weaker than an ε-band on p.
(b) SkillOpt: Pass^3 experimental→validated, Pass^5 + one repaired failure → production; prune if usage≥10 and success<0.40. RMAX-style optimism is absent: new skills are not treated as Rmax.
(c) A PAC attitude would refuse promotion until n supports the claimed band, and would explore unknown skills under a shield (sandbox), not in prod cron.
(d) Value: numerical PAC-MDP bounds are useless (|S| is language). Hoeffding/Wilson intervals on skill-quality jsonl are useful and cheap. Do not promote on one green run. Do not cite RMAX’s m as a Hermes hyperparameter.

Inverse RL from user corrections.
(a) IRL needs (near-)optimal occupancy. A correction is a local preference: “not this action / missing pitfall.” Identifiability fails; the implied R is a constraint or a negative example, not a unique scalar field.
(b) Hermes already maps corrections to skill pitfalls, failure jsonl, and human-gated patches (SkillEvo: ungoverned edits regress ~23% in days).
(c) Formal IRL (MaxEnt, occupancy matching) would require many trajectories of the same task class. You do not have that. Preference pairs (chosen vs corrected) are closer to DPO than IRL, and still too sparse to train.
(d) Value: low for recovering r; high for treating each correction as a hard constraint or a documented pitfall. That is apprenticeship as shielding, not as reward inference. If the same preference appears ≥3 times, promote to a generic skill — already the empirical rule — not to a personal R.

BOTTOM LINE

Hermes already implements the parts of RL theory that survive a non-stationary, language-state, one-shot-feedback world: hard constraints (CMDP feasible set / Lyapunov coordinates), options with explicit termination, knownness via repeated outcomes, and corrections as constraints. What does not transfer is solving MDPs: RMAX, dual-ascent Safe RL, PBRS on skill scores, option-critic, and IRL for a scalar user reward. Import the definitions. Do not import the solvers.
