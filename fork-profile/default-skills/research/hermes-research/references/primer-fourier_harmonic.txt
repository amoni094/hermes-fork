PRIMER: Fourier Analysis and Harmonic Analysis

=== FIELD OVERVIEW ===

Fourier Analysis decomposes functions and signals into sums of periodic basis functions (sines, cosines, complex exponentials). Harmonic Analysis generalizes this to functions on groups, manifolds, and abstract spaces. Core objects: the Fourier transform (maps time/space to frequency domain), convolution (multiplication in frequency domain), wavelets (localized frequency analysis), and spectral measures. Why it matters: many natural phenomena exhibit periodicity, oscillation, or repetition at multiple scales. Decomposing into frequencies reveals hidden structure, enables efficient computation via FFT, allows filtering, and provides concentration-of-measure bounds. For engineered systems, spectral methods reveal bottlenecks, cycles, and anomalies invisible in raw time-domain data.

=== KEY RESULTS ===

The Convolution Theorem: (f * g)(t) in time domain equals F(ω) · G(ω) in frequency domain (pointwise multiplication). This converts O(n²) convolution to O(n log n) via FFT. Parseval's Theorem: energy/norm is preserved across domains: integral of |f(t)|² equals integral of |F(ω)|². The Wiener-Khintchine Theorem links autocorrelation to power spectral density, essential for stochastic analysis. Discrete Fourier Transform (DFT) of length n computes in O(n log n) time via Fast Fourier Transform (FFT, Cooley-Tukey 1965). Wavelet Multiresolution Analysis: hierarchical decomposition into approximate (low-freq) and detail (high-freq) coefficients, enabling compression and multi-scale anomaly detection. The Uncertainty Principle: time and frequency localization trade off; narrow time windows yield broad frequency support and vice versa. Group Fourier Transform: extends to Lie groups and finite groups; particularly useful for analyzing symmetries and invariances in discrete systems.

=== STANDARD PRACTITIONER TOOLS ===

FFT libraries (NumPy.fft, SciPy.signal, FFTW). Welch's method for robust power spectral density estimation from short/noisy segments. Spectrograms (time-frequency decomposition via short-time FFT). Wavelet transforms (continuous and discrete; PyWavelets). Filtering (Butterworth, Chebyshev IIR/FIR in frequency domain). Autocorrelation and cross-correlation via Wiener-Khintchine. Peak detection in frequency domain. Detrending (linear, polynomial) before FFT to avoid spectral leakage.

=== HERMES APPLICATIONS ===

APPLICATION 1: TIME-SERIES ANALYSIS OF AGENT PERFORMANCE METRICS

Mathematical Structure: Agent metrics (latency, tool-call count, token consumption per turn) are time series. Fourier/wavelet analysis reveals periodicity (e.g., query bursts every N turns), trends, and anomalies. Autocorrelation identifies feedback loops. Power spectral density (PSD) shows which frequencies dominate variability.

Current Hermes Approach: Collect per-turn latency/tokens. Trigger alerts on threshold violation or rolling average spike. No frequency structure; treats each turn independently or via naive moving average.

Principled Approach: Compute DFT or continuous wavelet transform on windowed latency stream. Identify dominant frequency components. If latency oscillates at 3-turn period, that's evidence of systematic task queue backlog or model rotation pattern. Use Welch's method on overlapping 32-turn windows to estimate PSD robustly. Decompose into narrow-band (systematic) and broad-band (noise) components. Anomaly = spectral shape change or energy in unexpected frequency bands. Formula: Given latency vector L[0..n-1], compute L_hat = FFT(L); PSD = |L_hat|²/n; detect peaks above noise floor (e.g., median absolute deviation threshold in log-PSD).

Value Assessment: MODERATE-HIGH ROI. Latency oscillations are real (context compression, token budgets, model queue contention cause periodic behavior). Wavelet-based early warning (energy creeping into high-frequency band before threshold breach) could enable proactive rebalancing. Implementation cost: 20-40 lines of Python, minimal overhead (FFT is fast). Risk: real data may be too noisy to yield clean peaks, and causal interpretation (why that frequency?) requires deeper investigation. Safe spike: compute PSD on existing Hermes logs; if peaks exist at >3dB above noise, consider alert integration.

APPLICATION 2: SPECTRAL ANALYSIS OF CRON JOB PATTERNS

Mathematical Structure: Cron jobs fire at fixed intervals (25 jobs, ~25 different schedules). Superposition creates interference: some jobs batch, others spread load. The job schedule is a point process, whose power spectral density reveals harmonics (e.g., if three jobs run every 60 sec, they create peaks at 1/60 Hz and harmonics). Cross-spectrum between job firing and system resource usage reveals causality.

Current Hermes Approach: Track job runtimes, alert if job exceeds expected duration or resource quota. No analysis of job interaction or scheduling inefficiency.

Principled Approach: Model job schedule as a point process (spike train). For each job, generate binary indicator (0/1) at each time step. Compute DFT of aggregated indicator. Peaks in spectrum identify common intervals. Use coherence analysis (cross-spectrum magnitude normalized by marginal spectra) to detect which jobs "sync up". If coherence between research-sweep and model-routing jobs is high at 600-sec frequency, reschedule one to offset. Formula: For job J, define x_J[t] = 1 if J fires at time t, else 0. Aggregate x[t] = sum_J x_J[t]. Compute X = FFT(x); coherence(J1, J2) = |E[X_J1 · conj(X_J2)]| / (sqrt(|X_J1|²) · sqrt(|X_J2|²)).

Value Assessment: MODERATE. Scheduling conflicts exist but are rare and mild (25 jobs on modern multi-core system). Early return: check Hermes logs for job overlap and resource contention. If <5% of runs involve concurrent jobs, spectral optimization buys little. If >20%, a spectral audit to identify worst-offender pairs and propose phase-shift is worthwhile. Implementation: 50-100 lines for spike train analysis and coherence matrix. Risk: assumes periodic/quasi-periodic jobs; truly random arrival won't show spectral peaks. Conservative approach: use this for post-hoc analysis of why certain job combinations cause slowness, not for real-time rescheduling.

APPLICATION 3: FREQUENCY-DOMAIN ANALYSIS OF TOKEN USAGE

Mathematical Structure: Token consumption per turn is a sequence. Large language models exhibit regularities: certain task types (e.g., adversarial review, hermes-swarm-consensus) consume more tokens than others. Frequency analysis reveals periodicity in token allocation strategy. Cross-correlation between token usage and task type identifies systematic patterns.

Current Hermes Approach: Track cumulative token budget. Alert if overage or burn-rate too high. Allocate via static rules (e.g., "delegate_task gets 30% of budget").

Principled Approach: Treat token usage as a signal indexed by turn. Compute autocorrelation ACF[k] = E[(T[t] - μ_T)(T[t+k] - μ_T)] / σ_T². Significant peaks in ACF reveal cyclical token demands. Separately, segment turns by task type and compute power spectral density per task. Compare: if "adversarial review" token usage has higher power at low frequencies (meaning slower variation, more bursty), allocate larger buffer. If "model routing" is flat (uniform), use fixed slot. Use Hilbert transform to extract instantaneous frequency/amplitude of token envelope, detecting mode-switching.

Value Assessment: LOWER ROI. Token budget is managed by explicit per-model allocations, not dynamic frequency-dependent strategy. However, two wins: (1) post-hoc analysis to validate that current allocation matches empirical frequency structure (if theory matches practice, you have confidence; if not, investigation needed), (2) wavelet-based anomaly detection—if token usage suddenly shifts to a new frequency band, that signals a change in task mix or model behavior requiring investigation. Implementation: 30-50 lines for ACF/PSD computation and comparison. Risk: if task mix is already known and fixed, frequency analysis is redundant. Best use: non-real-time monitoring dashboard showing whether token spectrum is shifting month-to-month.
